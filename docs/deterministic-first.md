# Deterministic-First Design

Accounting truth should not be generated by an LLM. When a result can be derived from explicit inputs and rules, deterministic software is safer, easier to test, and easier to explain.

Examples of work that should prefer deterministic logic where possible:

- Totals and tax calculations
- Category rules
- Reconciliation checks
- Completeness checks
- Duplicate detection when stable identifiers or rules are available

The private application uses deterministic calculations, comparisons, and profitability indicators. This case study intentionally does not expose the actual formulas, categories, thresholds, or business-specific reconciliation rules.

Deterministic-first does not mean every input is unambiguous. It means uncertainty is represented explicitly and routed to validation instead of being hidden behind a confident-looking generated answer.
